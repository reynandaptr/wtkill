# wtkill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Rust TUI that finds `.worktree/` folders, shows each entry's disk usage and git state, and deletes finished worktrees safely via `git worktree remove`.

**Architecture:** Library crate (`src/lib.rs`) with focused modules plus a thin binary (`src/main.rs`). A pipeline thread discovers entries and streams `Update`s over an `mpsc` channel; sizes and git inspection run on rayon. `App` is a pure state machine consumed by both the ratatui UI and `--list`. All git work shells out to the `git` binary.

**Tech Stack:** Rust 2024 edition (toolchain 1.99.1), ratatui (+ its bundled crossterm re-export), clap (derive), rayon, serde + serde_json, anyhow, dirs; dev: tempfile.

**Spec:** `docs/superpowers/specs/2026-11-01-wtkill-design.md` — read it before any task; this plan argues from it.

## Global Constraints

- Default root: `~/Development/sourcecodes` (resolve `~` with `dirs::home_dir()`). *(Changed after release: the default is now the current directory.)*
- Directory names never descended into during discovery: `.git`, `node_modules`, `target`. Never recurse inside a `.worktree` dir beyond its immediate children.
- Never follow symlinks (discovery, size, delete).
- Size = sum of `st_blocks * 512`, each `(st_dev, st_ino)` counted once.
- Only network access: `git fetch --prune`, and only with `--fetch` or the `f` key.
- Every `git` call is `Command::new("git").arg("-C").arg(dir).args(..)` — paths go as separate args, never through a shell.
- Strict prompt requires the literal input `yes`; normal prompt accepts `y`/`Y`.
- Dirty-path list keeps the first 20; local-only commit subjects keep the first 10.
- Size formatting: binary units, labels `B KB MB GB TB`, one decimal above B (e.g. `38.0 GB`); partial sizes prefixed `≥ `.
- Build hygiene (user's CLAUDE.md): after build/test runs, make sure no `cargo`/`rustc` processes you started remain (`pgrep -a -u "$USER" 'cargo|rustc'`).

## Review Focus

1. **Names with spaces, `+`, unicode, and branches with `/`** (real example: `mobile-app-patch-4.1.10+423`, branch `feat/x`) — must scan, inspect and delete correctly. Pinned in Task 2 (fixture entry `app-feat x+1`) and asserted in Tasks 3, 5, 7.
2. **Relative `gitdir:` in the `.git` file** (git ≥ 2.48 `worktree.useRelativePaths`) — must resolve relative to the worktree dir, not cwd, so such worktrees aren't misclassified Broken. Pinned in Task 2 scan test.
3. **Overlapping roots** (`wtkill ~/src ~/src/personal`) — the same entry must appear once, or a double delete fires. Pinned in Task 2 scan test.
4. **Cursor/marks after rows disappear** (deleting the last row, or a marked row) — cursor clamps, marks of removed ids drop. Pinned in Task 6.
5. **Tiny terminal** (e.g. 40×10) — render must not panic or underflow. Pinned in Task 8.

### Task 6: App state machine (`app`)

**Files:**
- Create: `src/app.rs` (unit tests inline)
- Modify: `src/lib.rs`

**Interfaces:**
- Consumes: model types (Task 1), `Action` (Task 5).
- Produces:
  - `struct Row { entry: Entry, size: Option<Size>, git: Option<Result<GitInfo, String>>, status: RowStatus, note: Option<String> }` + `fn state(&self) -> Option<State>` (via `compute_state`)
  - `enum RowStatus { Idle, Deleting, Failed(String) }`
  - `enum SortKey { Size, Age, State }` — Size desc (unknown sizes last); Age = oldest `last_commit_unix` first (None last); State order `Done, Pushed, Orphan, Broken, Unknown, Risky, Clone`, then pending.
  - `enum Mode { Normal, Filter, Confirm { ids: Vec<usize>, action: Action, strict: bool, input: String }, ConfirmQuit }`
  - `enum Command { Delete { ids: Vec<usize>, action: Action }, Fetch, Quit }`
  - `struct App { pub rows: Vec<Row>, pub cursor: usize /* index into visible() */, pub marks: BTreeSet<usize> /* entry ids */, pub sort: SortKey, pub filter: String, pub mode: Mode, pub freed: u64, pub scanning: bool, pub roots: Vec<PathBuf>, pub message: Option<String> /* last delete note or error, shown in header */ }`
  - `App::new(roots: Vec<PathBuf>) -> App` (`scanning: true`)
  - `App::apply(&mut self, u: Update)` — `Found` pushes a Row; `Size`/`Git` fill in; `FetchFailed` sets `note` on rows whose `main_repo` matches; `ScanDone` clears `scanning`; `Deleted` adds the row's size bytes to `freed` and removes the row (and its mark), and sets `message` to `note` when present; `DeleteFailed` sets `RowStatus::Failed(err)`.
  - `App::visible(&self) -> Vec<usize>` — indices into `rows`, filtered by case-insensitive substring of the display path, sorted by `sort`.
  - `App::selected(&self) -> Option<&Row>`
  - `App::deleting(&self) -> bool`
  - `App::handle_key(&mut self, key: crossterm::event::KeyEvent) -> Vec<Command>` (use `ratatui::crossterm`). Keys per spec "TUI"; `d`/`D` target marked ids or the cursor row; if every target is `Clone`, set that row's note and open no prompt; Clone targets are dropped from a mixed set. `strict = any target state.is_strict()`. In Confirm: non-strict — `y`/`Y` confirms, anything else cancels; strict — chars append to `input`, `Backspace` edits, `Enter` confirms only when `input == "yes"`, `Esc` cancels. Confirm sets targeted rows to `Deleting`, clears marks, emits `Command::Delete`. `q`/`Ctrl-C`: `Quit` immediately unless `deleting()`, then `Mode::ConfirmQuit` (`y` → `Quit`).
